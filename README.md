# silo-web

Web frontend of SiloPost: a self-hosted IMAP/SMTP mail client with a Gmail-like UX.
React 19, TypeScript (strict), Vite and Tailwind CSS 4. Talks to
[`silo-server`](https://github.com/silopost/silo-server) through `/api/v1/*`.

## Development

```sh
npm ci && npm run dev
```

The dev server runs on http://localhost:5173 and proxies `/api` to `http://localhost:8080`.
Override the target with `VITE_API_PROXY`:

```sh
VITE_API_PROXY=http://silo.local:8080 npm run dev
```

Other scripts: `typecheck`, `lint`, `format:check`, `test`, `build`, `gen:api`.

Sign in with a mailbox of the dev stack (`dev1@silo.test` / `devpass1`, see the `silo`
README); `silo/scripts/dev-up.sh postgres mailserver silo-server` starts the backend only.

URLs are Gmail-like: `/u/<account index>/<label>` with system slugs (`inbox`, `starred`,
`snoozed`, `important`, `sent`, `scheduled`, `drafts`, `archive`, `all`, `spam`, `trash`) or a
label id (`l_…`), `/u/<n>/<label>/<threadId>` and `/u/<n>/search?q=`.

Tests (`npm test`) render the whole app with msw handlers (`src/test/mockMail.ts`, a stateful
fake server with threads, drafts, uploads, sending, contacts, search, snooze and several accounts; `mockLocal.ts` and `mockAdmin.ts` add mode `local`, TOTP, sessions and `/admin/*`), a fake `EventSource`
(`src/test/fakeEventSource.ts`) and a fake upload `XMLHttpRequest` (`src/test/fakeUploadXhr.ts`).

## Features (Faza 5)

What phase 5 of the plan adds to the web client (silo-server `faza-5` contract):

- **AccountSwitcher** (`src/features/account/AccountSwitcher.tsx`, the avatar in the top bar):
  every account of the user with its INBOX unread count (one `GET /labels?accountId=` per
  account under `['labels', accountId]`, kept current by `label.counts` of any account and
  refetched on `account.status`), its sync problem (`auth_failed`, `backoff`) as an icon with a
  tooltip, "Dodaj konto", "Zarządzaj kontami", "Wyloguj"; the badge on the avatar sums the other
  accounts' unread threads. Choosing an account opens `/u/<position>/<view>` (system views are
  kept, a user label falls back to `inbox`) and stores `PATCH /settings {activeAccountId}`;
  `g 1`…`g 9` do the same for the n-th account by `position`. `document.title` follows the tab's
  account ("Odebrane (3) – dev1@silo.test – Silo").
- **Od in compose** (more than one account, new messages only): the draft is created in the
  account of `/u/<n>`; another choice is `PUT /drafts/{id} {accountId}`, whose answer carries new
  `id`/`messageId`/`threadId` – the window follows the new id without remounting, the Drafts
  lists of both accounts refresh; `409 draft_account_locked` restores the choice.
  `draft.updated` with `previousDraftId` moves an open window in another tab.
- **Dodaj konto** (Ustawienia → Konta, `AddAccountDialog.tsx`, also `?add`): address and
  password → `POST /accounts/discover` (source shown: ISPDB / autoconfig / SRV / zgadnięte /
  serwer domyślny; "Zaawansowane" with host/port/TLS opens when nothing was found; read-only and
  not sent when `allowCustomServers=false`) → "Sprawdź połączenie" (`POST /accounts/test`, steps
  with ✓/✗) → "Dodaj" (`POST /accounts`; `422 account_test_failed` shows the steps, other codes
  a message) → the new account's inbox. "Zaloguj przez Google / Microsoft" for
  `meta.oauthProviders` (`POST /oauth/{provider}/start {returnTo}`, then the provider); back on
  `?oauth=ok|error&…` a snackbar or the Polish text of the code, and the URL is cleaned. The list
  shows OAuth accounts, "Zaloguj ponownie" for OAuth accounts in `auth_failed` (also in the
  account banner), "Zmień hasło" (`PATCH /accounts/{id}`) and "Usuń konto" (`DELETE`, confirmed).
- **Version banner** (`VersionBanner.tsx`): `__APP_VERSION__` (from `package.json`, Vite
  `define`) older than `meta.minWebVersion` → "Dostępna nowa wersja · Odśwież"; a different
  `serverVersion` after an SSE reconnect or the 15-minute `/meta` check → "Serwer został
  zaktualizowany · Odśwież". The app keeps working until the reload.
- **Session and limits**: SSE `session.expired` is handled like a 401 (session dropped,
  `/login?redirect=<page>`). `GET /events` with more than 8 streams per user answers 200 and a `stream.limit` event
  (`retryAfter` seconds) and closes: the tab closes its EventSource, polls `/events/poll`, shows
  "Zbyt wiele otwartych kart" and retries SSE after `retryAfter`. Any other
  `429 rate_limited` shows one snackbar with the `Retry-After` time (client middleware).
- **Mode `local` sign-in** (`src/routes/login.tsx`, `GET /meta authMode`): "Zaloguj się do Silo"
  without the mailbox hint. A user with TOTP gets `401 totp_required` after the right password;
  the page then asks for the 6-digit app code (numeric, `one-time-code`, autofocus) or "Użyj
  kodu zapasowego" and posts `POST /session {email, password, totpCode}` again (the password
  stays in component state only). Every `401` shows one message, "Nieprawidłowy e-mail, hasło
  lub kod"; `429` shows `Retry-After`. Mode `imap` is unchanged. A user without mail accounts
  (new local users) sees "Nie masz jeszcze konta pocztowego" with "Dodaj konto".
- **Ustawienia → Bezpieczeństwo** (`SecurityPanel.tsx`, mode `local` only; in `imap` the tab is
  hidden and the URL says "Niedostępne w tym trybie"): "Zmień hasło" (`POST /session/password`,
  10+ characters and the repeat checked first, `403` → "Nieprawidłowe hasło", the other
  sessions are signed out); TOTP on (`POST /totp/setup` → QR code of `otpauthUrl` drawn in the
  browser with `uqr`, the secret to type in, the code → `POST /totp/enable`, `422
invalid_totp_code` under the field) with the backup codes shown once (copy, download `.txt`,
  "Zapisałem kody" before closing); TOTP off and new backup codes after password + code (`DELETE
/totp`, `POST /totp/backup-codes`, `403` in the dialog); `GET /session` is refetched after each
  change. "Zalogowane urządzenia": `GET /sessions` with "Wyloguj" per session and "Wyloguj
  wszędzie indziej" (one `DELETE /sessions/{id}` each; there is no bulk endpoint).
- **Administracja** (`src/features/admin/`, `/u/<n>/admin/{users,accounts,jobs}`, in the account
  menu for `user.isAdmin` only; others and a `403 forbidden` get "Brak uprawnień"):
  Użytkownicy – accounts with their states, admin, blocked, TOTP, created; "Dodaj użytkownika"
  (mode `local`; an empty password gives `temporaryPassword`, shown once with "Kopiuj"),
  block/unblock and admin rights (`PATCH`), "Zresetuj hasło" (mode `local`, typed or generated,
  `PATCH {password}`), "Zresetuj TOTP", "Usuń" after typing the address; `409
admin_self_change` has its own message and the admin's own row disables those actions. Konta –
  every account with owner, host, coloured sync state, last sync, error, pending and dead
  operations (a link to Zadania of the account). Zadania – `dead` (default) or `pending`, per
  account, refreshed every 30 s while the tab is visible, "Ponów" / "Usuń" confirmed.
- **Ustawienia → Konta**: dead operations of an account (`sync-status.deadOps`) with "Zobacz w
  administracji" for admins, and a static "Kopia zapasowa" note (metadata backup vs. mail on the
  IMAP server, `scripts/backup.sh metadata|full` run by the administrator, link to
  `docs/admin/backup.md`).
- **PWA** (`vite-plugin-pwa`, `injectManifest` with `src/sw.ts`): `manifest.webmanifest` (Silo,
  standalone, icons 192/512, maskable, SVG; the PNGs are rasterised from `public/icons/icon.svg` by
  `npm run gen:icons`), precache of the
  build with `index.html` for every SPA route (never `/api/*`); runtime cache `silo-api-v1`,
  `NetworkFirst` with a 3 s timeout, 200 entries, 7 days, for `GET /threads`, `/threads/{id}`,
  `/labels` and `/messages/{id}/html` only (`src/pwa/cacheRules.ts`, unit-tested): never the
  session, `/meta`, `/events` or a mutation. Queries run with `networkMode: "offlineFirst"` so the
  worker can answer offline; mutations behave as before. Offline reload: the `_app` guard uses a
  snapshot of user, accounts and settings (localStorage, no CSRF token) only when the server is
  unreachable, and refetches `GET /session` on `online`. Sign-out, session loss and sign-in clear
  the API cache and the snapshot. A waiting new build shows "Nowa wersja aplikacji gotowa ·
  Odśwież" in the version banner (`registerType: "prompt"`). The worker runs in the production
  build only (`npm run build && npx vite preview`; HTTPS or `localhost`).
- e2e `multi-account.e2e.ts`, `pwa.e2e.ts` and `local-auth.e2e.ts`:
  [End-to-end tests](#end-to-end-tests).

## Compose

`src/features/compose` (plan 6.3): `ComposeDock` with Gmail-like windows (`state/compose.ts`:
open drafts and their mode – normal, minimised, full screen; at most three expanded),
`ComposeWindow`, `RecipientInput` (chips, `GET /contacts/autocomplete`), `Editor` (TipTap; pasted
HTML is reduced to its formats with DOMPurify) and `AttachmentList`. `session.ts` keeps the
editing state of an open draft outside React: `PUT /drafts/{id}` with `version` after 2 s of idle
time, on blur and on close; 409 shows "Wczytaj / Nadpisz". Uploads use `XMLHttpRequest` for
progress, three at a time. Sending is `POST /drafts/{id}/send` after the last save; "Cofnij" is
`POST /outbound/{id}/cancel`, whose `Draft` reopens the window. The server owns autosave,
deduplication and the send queue (plan 2.6); the browser keeps no copy of drafts and only warns
on leaving the page with unsaved edits.

## Search

`src/features/search` (plan 3.12, 6.3). The client has no query parser (plan 2.6): the text in
the box is sent as `q` to `GET /threads` and the server parses it. The operators (`from:`,
`to:`, `subject:`, `label:`, `in:`, `is:`, `has:`, `before:`/`after:`, `older_than:`,
`larger:`, `OR`, `-`, brackets, "phrases"...) are described in the
[silo-server README](https://github.com/silopost/silo-server#configuration) (search section) and
in `api/openapi.yaml`.

- `SearchBox`: a combobox (`aria-autocomplete="list"`, listbox grouped as Ostatnie / Kontakty /
  Etykiety / Operatory) fed by `GET /search/suggest` 150 ms after typing; accepting a suggestion
  puts its `text` (the whole query) in the box, a recent query searches at once. History entries
  are removed with their × button or Shift+Delete (`DELETE /search/history?query=`), all of them
  with "Wyczyść historię". Enter → `/u/<n>/search?q=`; `/` focuses the box, Esc leaves it.
- `SearchChips` (`SearchHeader.tsx`): the query split at the spaces outside quotes and
  brackets, for display only; removing a chip removes that text from `q`.
- `AdvancedSearchPopover`: Gmail's options (from, to, subject, words, without, attachment,
  size, date range, where) joined into the text of `q` (`lib/searchText.ts`). "Utwórz filtr"
  opens `/u/<n>/settings/filters?criteria=<q>` with a new filter (see Filters).
- Results show "Indeksowanie treści: NN% – wyniki mogą być niepełne" while `indexing.done < 1`,
  a notice when the search hit the server's time limit (`approximate`), the estimate ("ok. 1240
  wyników", "2000+ wyników") and `422 invalid_query` under the box.

## Snooze

`src/features/snooze` (plan 3.10): `SnoozeMenu` lists `GET /snooze/presets` (computed by the
server in the user's time zone; the menu translates the label by `key` and formats `until`)
and "Wybierz datę i godzinę" (a `datetime-local` field whose value is sent as RFC 3339). It is
offered by the row (hover), the list toolbar for the selection (one `POST /threads/{id}/snooze`
per thread, at most 50), the thread view and the `b` shortcut. The threads leave Inbox at once;
"Cofnij" undoes every operation (`POST /operations/{id}/undo`). "Odłożone" (`SNOOZED`) shows
the wake time in orange, "Wybudź teraz" (`DELETE /threads/{id}/snooze`) and "Zmień termin";
the thread view of a snoozed thread says until when.

## Scheduled

The arrow next to "Wyślij" opens "Zaplanuj wysyłkę": the `tomorrow` and `next_week` snooze
presets of the server ("Jutro rano", "W poniedziałek rano") and a picked date and time, sent as
`POST /drafts/{id}/send {sendAt}`; the snackbar's "Cofnij" cancels it. "Zaplanowane"
(`SCHEDULED`) lists the messages with their `scheduledAt`; "Anuluj wysyłkę" is
`POST /outbound/{outboundId}/cancel`, whose draft opens in a compose window.

## Attachments & inline images

- Files are attached by the paperclip, drag and drop or paste: `POST /uploads` (multipart,
  `XMLHttpRequest` for progress, three at a time); `413 upload_too_large` names the limit. The
  ids go to `PUT /drafts/{id}` as `attachmentIds`.
- Pictures pasted or dropped into the text are inline uploads: the form field `inline=true` goes
  before the file and the server generates the Content-ID (`UploadInfo.cid`); the client never
  makes one up. While uploading, the editor shows a local preview; afterwards it shows the
  upload itself (`GET /attachments/{u_…}?inline=1`) and keeps the cid in `data-cid`.
  `bodyHtml` of `PUT /drafts/{id}` carries `<img src="cid:…">`; a draft loaded from the server
  is converted back (`lib/inlineImages.ts`). Inline pictures are not listed in
  `AttachmentList`, and removing one from the text unpins its upload from `attachmentIds`.
- Thumbnails: when the server says `thumbnail: true`, the chip (thread and compose) loads
  `GET /attachments/{id}/thumbnail?size=s` lazily; otherwise, or on error, the type icon.
- Forward (`POST /drafts {mode: forward}`) gets the original attachments from the server; its
  `warnings` (`quote_unavailable`, `attachments_unavailable`, `attachments_too_large`) are shown
  in a snackbar.

## Settings

`/u/<n>/settings/…` (`src/features/settings`, plan 6.5), each tab its own route:

- **Ogólne** (`GeneralSettings`): density, undo-send seconds, signature, time zone, keyboard
  shortcuts on/off, conversation view and desktop notifications. Every change is one
  `PATCH /settings` with one field (JSON merge); the answer replaces the cache and the session's
  copy, `422 invalid_setting` / `invalid_timezone` show a snackbar. Desktop notifications ask
  for the browser's permission first and are shown on `message.new` events.
- **Etykiety** (`LabelsPanel`): see Labels.
- **Filtry** (`FiltersPanel`, `FilterEditor`): see Filters.
- **Konta** (`AccountsPanel`): the accounts in `position` order with their state and errors;
  "Odbuduj cache" is `POST /accounts/{id}/resync {mode: rebuild}` (`409 rebuild_blocked` while
  a send or a write-back waits). Faza 5: "Dodaj konto", OAuth, password change and removal (see
  [Features (Faza 5)](#features-faza-5)).

## Labels

User labels (IMAP keywords) and server folders, both from `GET /labels`. The settings tab shows
them as trees by `parentId`, with colours (`colorBg` / `colorText`), "Pokaż na liście" and
counts; create is `POST /labels` (`type: user` or `folder`), rename / colour / visibility
`PATCH /labels/{id}`, delete `DELETE /labels/{id}` (a folder only when empty). The parent of a
user label ("Zagnieżdż w") is set at creation and changed later with `PATCH /labels/{id}`
`{parentId}` (`null` = top level; the label itself and its descendants are not offered, and
`422 invalid_parent` is shown under the field). The keyword does not change with the parent.
`keywordState` `local_only` / `partial` shows a warning next to the label, in the settings and
in LeftNav. Threads are labelled from the toolbar popover or `l`, moved with "Przenieś do" or
`v` (a folder label is a folder change in the Gmail model: the target is added, `INBOX` and the
other folder labels of the threads removed; the server moves the messages after the undo
window).

## Filters

`GET/POST/PUT/DELETE /filters`: criteria are a query of the search syntax (parsed and evaluated
only by the server), actions are archive, mark read, star, important, trash, add labels and
forward. `POST /filters/{id}/apply` runs a filter on existing mail and shows the server's
estimate. "Utwórz filtr" in the advanced search opens `/u/<n>/settings/filters?criteria=<q>`
with a new filter. `422 invalid_query` / `invalid_filter` / `invalid_label` are shown in the
editor.

## Shortcuts

`src/shortcuts/keymap.ts` is the only list; the `?` dialog is generated from it. Keys are
matched by `event.key` (so `#`, `!`, `?` and `*` work on the Polish layout). The dispatcher
ignores keys typed in `input`, `textarea`, `select` and `[contenteditable]`, inside dialogs,
menus and popovers (they have their own keys), during IME composition and with Ctrl/Alt/Meta.
Sequences (`g …`, `* …`) wait 1500 ms for the second key. "Skróty klawiszowe" off in the
settings (`keyboardShortcutsEnabled`) turns the dispatcher off; the keys handled by the
components themselves (Esc, Ctrl/⌘+Enter in compose, the keys of fields and menus) keep working.

## End-to-end tests

`e2e/` holds the Playwright tests of the Faza 3 Definition of done (plan, section 7): reply
delivered with `In-Reply-To`/`References`, archive and its undo, undo send, drafts in the
server's Drafts folder, the mail server going offline, a 5000-thread list without long tasks,
hostile HTML, keyboard shortcuts and axe (`@axe-core/playwright`). They run against the full dev
stack and check the mail server's state over IMAP (`imapflow`), as a second client would.

Faza 4 (plan, section 7) adds:

| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search.e2e.ts`          | `from:`, `has:attachment`, `is:unread`, `subject:`, words, `-word`, `OR`, `label:` on mail seeded over IMAP; history and contact suggestions, chips, the advanced search, `422` for a stray `)`, the indexing banner when shown |
| `snooze.e2e.ts`          | snooze "in a minute": in `Snoozed` on the server and not in INBOX, back in INBOX without `\Seen` within 90 s and on top of the list (@slow); Cofnij, Odłożone and "Wybudź teraz"                                                |

| `schedule-send.e2e.ts`   | a message scheduled about 2 minutes ahead is in no folder of the sender nor in the recipient's INBOX before its time and arrives within ±30 s (@slow); Zaplanowane and "Anuluj wysyłkę"                                         |
| `labels-keywords.e2e.ts` | a label from Silo is a keyword on the server; a keyword stored by another client is a label on the row within 5 s                                                                                                               |

```sh
docker compose -p silo-bt -f docker-compose.backup-test.yml up -d --build
SILO_COMPOSE_FILE=docker-compose.backup-test.yml scripts/seed-mail.sh
SILO_COMPOSE_FILE=docker-compose.backup-test.yml scripts/seed-mail.sh --to dev2@silo.test
# in silo-web
SILO_E2E_API=http://localhost:18080 SILO_DEV_IMAP_PORT=11143 SILO_E2E_WEB_PORT=15180   SILO_UNDO_WINDOW=1s npm run e2e -- multi-account
# in silo, afterwards
docker compose -p silo-bt -f docker-compose.backup-test.yml down -v
```

`pwa.e2e.ts` runs on the same stack (mode `imap`, dev1): service worker and manifest, the inbox
and a thread read online, then `context.setOffline(true)`; a reload shows the shell, the cached
list and thread body and the offline banner; back online the list loads again.

`local-auth.e2e.ts` needs silo-server in mode `local` (`docker-compose.local-auth.yml` in `silo`)
and a first admin (`SILO_E2E_ADMIN_EMAIL` / `SILO_E2E_ADMIN_PASSWORD`, default
`admin@silo.test` / `admin-e2e-password`): TOTP on (codes computed by `e2e/support/totp.ts`),
sign-in with the code, a user created in Administracja signs in with the temporary password in a
second context, adds `dev1@silo.test` (`mailserver:143`, no TLS) and sees its INBOX; the admin
removes the user and turns TOTP off with a backup code, so the run can be repeated:

```sh
# in silo, on a fresh database (dev1@ must not belong to a user of mode imap)
docker compose -p silo-bt -f docker-compose.backup-test.yml -f docker-compose.local-auth.yml up -d --build
echo 'admin-e2e-password' | docker compose -p silo-bt -f docker-compose.backup-test.yml \
  -f docker-compose.local-auth.yml exec -T silo-server /silo-server user add \
  --email admin@silo.test --admin --password-stdin
SILO_COMPOSE_FILE=docker-compose.backup-test.yml scripts/seed-mail.sh
# in silo-web
SILO_E2E_API=http://localhost:18080 SILO_DEV_IMAP_PORT=11143 SILO_E2E_WEB_PORT=15180 npm run e2e -- local-auth
# in silo, afterwards
docker compose -p silo-bt -f docker-compose.backup-test.yml -f docker-compose.local-auth.yml down -v
```

The tests tagged `@slow` wait for real time (snooze and schedule send, 2–4 minutes each); skip
them with `npm run e2e -- --grep-invert @slow`. Labels, filters and settings changed by a test are
removed or restored afterwards through the API (`e2e/support/api.ts`, a bearer session). The
`local_only` / `partial` keyword warnings are not exercised end to end (they need a server without
keywords or a folder with 26 keywords; silo-server covers them against Dovecot). Dovecot may keep
keywords in a maildir folder's keyword list after the messages are gone, so many runs against the
same dev mailbox can approach the 26-keyword limit; recreate the dev mailserver volume when labels
start showing `partial`.

```sh
# in silo: backend, mail server and mail seed (once)
scripts/dev-up.sh postgres mailserver silo-server
scripts/seed-mail.sh --all
# in silo-web
npx playwright install chromium   # once
npm run e2e                       # all tests; e.g. `npm run e2e -- archive` for one file
```

`npm run e2e` builds the app and serves it with `vite preview` on port 5180 (`SILO_E2E_WEB_PORT`),
proxying `/api` to silo-server at `SILO_DEV_SERVER_PORT` from `silo/.env` (`SILO_E2E_API` overrides
it); `SILO_E2E_WEB_URL` tests an already running instance. The IMAP port comes from
`SILO_DEV_IMAP_PORT`, the `silo` checkout from `SILO_DIR` (default `../silo`). Tests run one at a
time on the shared dev mailboxes; each marks its mail with a unique tag in the subject and
deletes it afterwards. The 5000-thread corpus is APPENDed once to `dev3@silo.test` and kept
(`SILO_E2E_BULK_THREADS` changes the size). The offline test stops and starts the `mailserver`
container. Measurements are printed as `[measure]` lines. In CI the `e2e` job runs on demand
(`workflow_dispatch`).

## API contract

Types in `src/api/schema.d.ts` are generated by `openapi-typescript` from
`api/openapi.yaml` of [`silo-server`](https://github.com/silopost/silo-server) and
committed. The server release this web build targets is declared in `package.json`
as `silo.serverRef` (a git tag or branch; currently `v0.4.0`).

```sh
npm run gen:api                          # fetch the file at silo.serverRef
npm run gen:api -- --server-ref v0.3.0   # fetch from another ref
npm run gen:api -- --local               # read ../silo-server/api/openapi.yaml
npm run gen:api -- --local path/to/openapi.yaml
```

After changing `silo.serverRef`, regenerate and commit the schema. The `api-contract`
CI job checks out `silo-server` at that ref, regenerates the schema and fails on any diff.
Until `silopost/silo-server` is public, that job is expected to fail at the checkout step.
